# 実装フェーズ・検証計画

## 実装の前提

この計画は技術スタックを固定しない。作業開始時にリポジトリの構成、既存コード、実行・公開方法を確認し、既存の選択がなければ静的データと小さなWeb UIから始める。データベース、ログイン、投稿機能は初期要件に含めない。

## フェーズ0：リポジトリ確認と決定事項の記録

- 既存ファイル、フレームワーク、パッケージ管理、実行スクリプト、公開先を調べる。
- git状態を確認し、既存の変更を保護する。
- 利用可能な技術が未決定なら、静的サイトに適した候補を比較し、採用理由を記録する。
- `.gitignore`、README、Claude Code指示、データ配置場所を整える。
- サイト名の公開利用、ドメイン、既存の tariki-code.tokyo との関係を決定事項として保留管理する。

**完了条件:** 技術選択とローカル起動方法が文書化され、企画とデータ設計に矛盾がない。

## フェーズ1：データ基盤

- 機能ID、地域コード、プラットフォーム、状態値を定義する。
- サービス、機能主張、料金、根拠、提供状況の構造を実装する。
- JSON Schema等のバリデーションを導入し、ID重複や根拠漏れを検出する。
- サンプルは、架空のサービス名・`example.invalid` ドメイン・「架空」の明記を備えた開発用フィクスチャに限る（`data/fixtures/`）。公開ビルドには含めず、仮の機能状態を実在サービスとして公開しない（[decisions.md](decisions.md) D3）。
- 候補サービスを調査し、根拠が揃ったものからおよそ20〜30件を選ぶ。

**完了条件:** データ更新手順が明確で、公開レコードの機能・価格・提供範囲を出典と日付まで追跡できる。

## フェーズ2：図鑑の基本UI

- トップページに概要、検索欄、フィルター、件数、サービス一覧を配置する。
- 名称・提供元検索を実装する。
- 地域、機能、言語、環境、無料利用などの基本絞り込みを実装する。
- 同一フィルター群内はOR、異なる群の間はANDで組み合わせる。
- カードには短い紹介、地域、確認済み機能、確認日を表示する。
- 詳細表示では機能の条件、価格条件、根拠URL、確認日を閲覧できる。
- 未確認と非対応を視覚・文言の双方で区別する。

**完了条件:** 利用者が「画像生成と音声会話の両方を探す」等の検索を行い、条件を解除できる。

## フェーズ3：品質、アクセシビリティ、公開準備

- モバイル幅、キーボード操作、フォーカス順、ラベル、色コントラストを確認する。
- 外部リンクと免責・編集方針を確認する。
- 全公開データについて公式ソース、地域、プラン、確認日、リンク切れをレビューする。
- サービス名「AI Atlas」の名称重複、公開URL、サイト公開設定を確認する。
- 公開前の更新日を記録し、記事化する場合の表現と図鑑データを一致させる。

**完了条件:** 一般ユーザーが誤解なく閲覧でき、全ての時点依存の主要情報に根拠がある。

## フェーズ4：運用と拡張

- 四半期ごとの棚卸しを初期運用案として設定し、料金・地域・主要機能は公開前にも確認する。
- 変更・終了・名称変更を記録し、過去の情報を削除せず履歴化する。
- 必要性が確認できた後に、並列比較、URL共有、英語表示、更新履歴を追加する。
- 収録数を増やすより、データの正確さと対象地域のバランスを優先する。

## 検証手順

### 1. 公式一次ソースの確認

優先順位は、公式の製品ページ、ヘルプセンター、料金ページ、提供地域ページ、公式リリースノート、公式アプリストア掲載情報。各ページの正確なURL、確認日、表示言語、確認した事実を記録する。

公式情報が見つからない場合は `unknown` とする。第三者記事のみで補った値を公式確認済みとして表示しない。二次情報を採用する場合は出典の性格を明記し、公式情報と混在させない。

### 2. 主張を分割して確認

「画像生成に対応」のような曖昧な一括記述を避け、少なくとも次を確かめる。

- どの地域で使えるか。
- 無料・有料のどのプランで使えるか。
- Web、iOS、Android等のどこで使えるか。
- チャットサービス内の機能か、別製品・連携先・APIの機能か。
- 利用制限、提供段階、アカウント条件があるか。
- 情報をいつ確認したか。

### 3. 公開前チェック

- サービスの現行名称と運営状況。
- 公式URLと提供元。
- 提供元の拠点とサービス提供地域の区別。
- 日本での提供可否を含む地域条件。
- 機能と機能分類の説明。
- UI言語と会話言語の区別。
- 無料枠、価格、通貨、請求期間、税・制限の注記。
- 公式ページのリンクと確認日。
- 機能ステータスと詳細ページの説明が一致している。

## 初期版で後回しにするもの
