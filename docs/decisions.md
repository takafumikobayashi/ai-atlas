# 決定事項と保留事項

## 決定事項

### D1. 技術構成：依存パッケージなしの静的サイト（2026-11-14）

- **画面:** 素のHTML・CSS・JavaScript（ESモジュール）。ビルド処理やフレームワークは使わない。
- **データ:** `data/` 配下のJSONファイル。画面のコード（`site/`）とは分けて管理する。
- **検証・ビルド・開発サーバー:** Node.js（20以上）の標準機能だけで書いたスクリプト。`npm install` は不要。
- **テスト:** Node標準の `node:test`。

**理由**

- 初期版は20〜30件の静的な図鑑で、データベースや実行時APIの要件がない（CLAUDE.md、requirements.md 7章）。
- 一番重要な品質要件はデータの正確さと追跡しやすさ。必要なのは画面の機能よりも、データ検証の仕組みである。
- 依存パッケージがなければ、更新作業やセキュリティ対応の負担がほぼない。公開先も、静的ファイルを置ける場所ならどこでもよい。
- 画面が複雑になり、型やコンポーネントが必要になったら、Vite や Astro などへ移行を検討する。データ（`data/`）と絞り込みロジック（`site/js/filter.js`）は画面から独立しているので、そのまま移せる。

### D2. ディレクトリ構成

| パス | 内容 |
|---|---|
| `data/services.json` | 公開用の掲載データ。検証済みのレコードだけを入れる |
| `data/vocabulary.json` | 状態値・機能ID・分類・環境などの語彙と表示名。画面と検証スクリプトで共有する |
| `data/fixtures/sample-services.json` | 開発・テスト専用の架空データ。公開ビルドには含めない |
| `site/` | 画面（`index.html`, `styles.css`, `js/`） |
| `scripts/` | 検証・ビルド・開発サーバー |
| `test/` | 絞り込みロジックと検証ルールのテスト |
| `dist/` | ビルドの出力先（git管理外） |

### D3. 架空サンプルデータの扱い

画面と絞り込みの動作確認には、さまざまな状態値を持つデータが必要になる。そこで、架空のサービス名、`example.invalid` ドメイン、「架空」と明記した説明を使ったフィクスチャを用意する。

- 開発サーバーで `?sample` を付けたときだけ読み込み、画面に「サンプル表示中」の帯を出す。
- `npm run build` の出力には含めない。
- 検証スクリプトは、公開データに例示用ドメインがあるとエラーにする。

### D4. 機能フィルターの組み合わせ

基本ルールは「同じグループ内はOR、グループ間はAND」。ただし「画像生成と音声会話の両方」を探せるように（implementation-plan.md フェーズ2の完了条件）、機能グループだけは「いずれか（OR、既定）／すべて（AND）」を切り替えられるようにする。

機能フィルターは `supported` と `conditional` を「使える」として扱う。条件付きの機能は、カードと詳細画面で「条件付き」と明示する。

別の製品・アプリでだけ提供される機能（`delivery: separate_product`）も、絞り込みでは「使える」に含める。詳細画面では提供形態として「別の製品・アプリ」と表示する（2026-11-14 決定）。

### D5. 「要再確認」の基準

確認日から **90日** を過ぎた主張を「要再確認」と表示する。四半期ごとの棚卸しに合わせた値で、`data/vocabulary.json` の `staleAfterDays` で変更できる。検証スクリプトでは警告として出し、`--strict` のときだけエラーにする。

### D6. 提供終了サービスの扱い

`lifecycle.status` が `discontinued` のレコードは、データ上は履歴として残し、一覧には表示しない。

### D7. デザインの方向性：オフコン端末の画面 × 文字の地球儀（2026-11-14 改訂）

- **土台：** code.storage の構成に寄せた。左寄せの等幅テキストの段組み、`# 見出し`、`*` の箇条書き、文字で組んだ表（`+---+`）、右側のビジュアルと点線でつないだ注記。同サイト固有の3Dオブジェクトや文言は使っていない。
- **日本の汎用機・オフコン端末の要素：** 画像（AS/400 の日本語メニュー画面、ISPF の画面）を参考に、次の決まりごとを取り入れた。製品名・ロゴ・画面の文言は使っていない。
  - 最上段の画面ID・タイトル・日付（`ATLAS01` 一覧／`ATLAS02` 詳細）と、その下の青い破線
  - 番号付きの「メイン・メニュー」（「次から 1 つを選択してください。」、右側に英字のコマンド名）
  - `選択項目またはサービス名 ===>` のコマンド行。番号で移動、それ以外は名前検索
  - `サービス名・提供元 . . . .` のような点線のリーダーと、下線だけの入力欄
  - 画面下のキー案内（`/=検索` `Esc=一覧に戻る` `C=条件をクリア` `M=メニュー`）。すべて実際に動く。入力中は無効で、F1〜F12 や Ctrl/Cmd との組み合わせなど、ブラウザのキーは奪わない。スマートフォン幅では表示しない
  - リストの最後の「終わり」、枠線で囲んだ注記
- **フォント：** BIZ UDゴシック（Google Fonts、等幅版）。英数は8px、かなと漢字は16pxのちょうど1対2なので、日本語を含む表でも罫線が揃う（表の幅計算は `app.js` の `cellWidth()`）。当初はドット絵風の DotGothic16 を使ったが、表示環境によって字形が崩れて見えたため切り替えた。強調は文字の太さではなく色（白）で表し、緑の要素だけにブラウン管のような軽い発光を付ける。
- **右側のビジュアル：** 文字で描いた回転する地球儀（`site/js/globe.js`）。掲載サービスの提供元がある国を `@` と国コードで示し、「提供元の拠点」で絞り込むと該当国だけが明るくなる。フォントの縦横比を実測して円く描く。装飾なので読み上げ対象外。「動きを減らす」設定のときは回転を止める。
- **配色：** ダークのみ。背景 `#0C0C0C`、本文 `#D2D2D2`。カーソル・プロンプト・選択状態・メニュー・地球儀の印には、昔の端末の蛍光体のような緑（`#4DFF7C`）を使う。リンクは青、条件付きは琥珀色、非対応は赤。状態は `[✓ 対応]` のように記号と文言で示し、色だけに頼らない。
- **アクセシビリティ：** 文字で組んだ表は見た目用で、同じ内容の `<table>` を読み上げ用に隠して置いている。コマンド名の列やコマンド行の表示は装飾なので読み上げ対象外（件数は別途読み上げる）。
- **注意点：** Google Fonts を使うと、閲覧者のIPアドレスが Google に送られる。気になる場合は、フォントを `site/` に同梱する方式（自前配信）に切り替える（BIZ UDゴシックは SIL Open Font License）。

### D8. 公式ページの OGP 画像を表示する（2026-11-14）

- 一覧の各サービスに小さく、詳細画面に大きく、公式ページの OGP 画像（`og:image`）を表示する。デザインの方向性（D7）とは異なる見た目になるが、サービスを見分けやすくするために採用した。
- 静的サイトでは閲覧時に他サイトの HTML を読めない（CORS）ため、作業時に `scripts/fetch-previews.mjs` で画像URLを取り出し、`data/services.json` の `officialPreview` に取得元と確認日とともに記録する。
- 画像はコピーせず、提供元のサーバーから直接表示する（リンクプレビューとしての使い方）。読み込めない場合は画像の枠ごと隠す。
- 画像の取得元は公式のユーザー向けページに限る。Claude は claude.ai の画像が外部からの表示を禁止していたため、公式製品サイト claude.com の画像を使っている。
- 注意点：閲覧時に提供元のサーバーへ画像のリクエストが送られる（リファラーは送らない設定）。気になる場合は、画像を `site/` に保存して配信する方式に切り替える。その場合は各社の利用条件を確認する。

### D9. 初めての人が迷わないための整理（2026-11-14、外部レビューを反映）

- **絞り込み：** 最初に見せるのは「サービス名検索」と「できること」だけにする。拠点・言語・利用環境・料金は「詳細条件」として折りたたむ（`<details>`）。閉じていても選択中の条件があれば「N件を選択中」と表示し、見えない条件で結果が絞られたままにならないようにする。
- **一覧と詳細の役割分担：** 一覧は、名前・提供元（国旗付き）・紹介文・できること（最大5つ。テキストチャットは全サービス共通なので省く）・無料プランの有無・最新の確認日だけを表示する。「日本で」の状態、未確認の件数、条件、出典は詳細画面で見せる。未確認の多いサービスが一覧で劣って見えないようにするため。
- **サンプル表示：** 注意書きはサンプル表示のときだけ JavaScript で作る。公開ページの HTML には含めない（非表示の要素を読み取るツールで誤解されないため）。
- **キー操作：** 番号入力やキー案内は近道であり、すべての操作はマウス・タッチだけでもできる状態を保つ。
- **広い画面の余白：** 本文の列は読みやすさのため約44文字（704px）のまま広げない。右側は「地図の領域」として使い、地球儀を中央に置いて画面幅に応じて大きくする（13〜18px）。全体の最大幅は 2000px で、左寄せ（端末の画面のように）を保つ。

### D10. サイトの OGP 画像とファビコン（2026-11-14）

- **OGP 画像：** `site/og-card.html` をサイトと同じ HTML・CSS で作り、`npm run og`（`scripts/build-og.mjs`）でヘッドレス Chrome により `site/og-image.png`（1200×630）にする。画像の中の文言は実際のサイトに合わせ、存在しない機能や、古くなる日付・件数は入れない。地球儀の `@` は公開データにある提供元の国から描く。`og-card.html` は公開ビルドに含めない。
- **OGP の URL：** `og:image` は絶対 URL が必要なため、`SITE_URL=https://… npm run build` で絶対 URL と `og:url` に置き換える。公開ドメインが決まるまでは相対パスのまま。
- **ファビコン：** ブラウザのタブ（16px）では細部がつぶれるため、16×16 のマス目で描いた地球儀の SVG（`site/favicon.svg`）を使う。32px の PNG とホーム画面用アイコン（180px）には、提案された窓と地球儀のドット絵を縮小して使う。

### D11. 公開名・ドメイン・公開先（2026-11-14）

- **公開名：** 「AI Atlas」とする。商標に同名の登録がないことは利用者が確認済み。同じ分野に同名・類似名のサイト（CNET の「AI Atlas」、aiatlas.app など）があるため、「対話型AIサービス図鑑」を添えて区別する。
- **ドメイン：** `ai-atlas.tariki-code.tokyo`（tariki-code.tokyo のサブドメイン）。
- **公開先：** Cloudflare Pages。手順は [deploy.md](deploy.md)。`npm run build:prod` で og:image を絶対 URL にしてビルドする。
- **レスポンスヘッダー：** `site/_headers` で CSP などを設定する。開発サーバーも同じヘッダーを付けるため、手元で CSP の違反に気づける。
