# AI Atlas 企画・要件

## 1. プロジェクト概要

世界中の対話型AIサービスを、名称だけでなく機能や利用条件から探せる「図鑑」サイトを作る。単なるニュース記事や人気順ランキングではなく、AIコミュニティの参加者や初心者が、各サービスの違いを把握して試すサービスを選べる情報源を目指す。

- **プロジェクト名:** AI Atlas（候補。公開名称の重複・商標・ドメインは別途確認）
- **コンセプト:** 世界のAIを、見つける・知る・比べる。
- **英語説明案:** An open directory of AI assistants. Explore and compare AI tools by features, capabilities, and regions.
- **想定公開先:** 独立したWebサイト。既存サイト tariki-code.tokyo との連携は将来案であり、実装先やURLは未決定。
- **初期収録規模:** 20〜30サービス程度を目安に選定。件数を満たすために未確認情報を公開しない。

## 2. 対象ユーザーと課題

主な利用者は、AIコミュニティのメンバー、AIサービスに興味を持ち始めた人、目的に応じて複数のAIを使い分けたい人。

解決したい課題:

- ChatGPT以外にどのような対話型AIがあるか分からない。
- 画像生成、音声会話、ファイル読込など、やりたいことに合うサービスを探しにくい。
- サービスごとに機能がどのプラン、地域、端末で使えるか分かりにくい。
- 変化の速い料金・提供状況について、情報がいつ、何を根拠に確認されたか分からない。

## 3. 掲載範囲

### 初期版に含める

- 一般ユーザー向けに公開され、Webまたはスマートフォン等から利用できる対話型AIサービス。
- 自然言語で会話でき、独立したサービス名があるもの。
- 知名度だけでなく、独自性、地域的な重要性、用途上の特徴を考慮して選んだもの。
- 米国・中国だけに偏らないよう、地域の広がりを検討する。
- サービス名、提供元、公式URL、説明、機能、言語、利用環境、提供地域、料金区分、根拠、確認日。

### 初期版では原則含めない

- APIだけで提供される基盤モデル。
- 開発者向けCLIなど、一般ユーザー向けの会話サービスではない製品。
- 画像・動画生成だけを行い、対話型アシスタントを提供しない専用サービス。
- 一般公開されていない社内専用チャットボット。

境界にある製品は、名称やカテゴリーだけで自動判断せず、利用者が会話形式のサービスとして使えるかを記録し、採否を説明する。

## 4. 機能分類

機能は、利用者がやりたいことを軸に用意する。名称や説明は日本語UIで分かりやすい表現に調整してよい。

| ID案 | 表示名 | 説明 |
|---|---|---|
| text_chat | テキストチャット | 文章でAIと対話する |
| web_search | Web検索・調査 | Web情報を検索し、回答や調査に使う |
| image_generation | 画像生成 | 指示から画像を生成する |
| video_generation | 動画生成 | 指示等から動画を生成する |
| voice_conversation | 音声会話 | 音声で双方向に会話する |
| file_analysis | ファイル読込・解析 | PDFや文書などを読み込み質問・要約する |
| data_analysis | データ分析 | CSV、表計算等を分析する |
| code_generation | コード作成支援 | コードを生成・説明・修正する |
| agent_tasks | エージェント・作業実行 | 複数ステップの作業を進める |
| document_creation | 資料・文書作成 | レポートやスライドなどを作る |

カテゴリは管理可能な識別子として保持し、表示文言はUI側で管理する。

## 5. 比較・検索要件

### 初期版の基本機能

- サービス名または提供元で検索。
- 機能、提供元の地域、言語、利用環境、無料利用の有無で絞り込む。
- 複数の絞り込みを組み合わせる。各グループ内はOR、グループ間はANDを基本とする。
- 条件クリア操作と検索結果件数を表示する。
- サービスカードに名称、提供元、短い説明、地域、主要機能の確認状態、確認日を表示する。
- 詳細画面または詳細ページで、条件・根拠・公式URLを確認できる。
- 機能の状態は色だけで示さず、テキスト・アイコン等も併用する。
- 公式サイトへの外部リンクであることを明示し、提携・推奨と誤認させない。

### 後続候補

- 複数サービスを並べて比較。
- 地域・プラン・日付を指定した比較。
- 絞り込み状態をURLで共有。
- 英語等への多言語化。
- 更新履歴・変更点の表示。

## 6. 情報表示の原則

- 「対応」と「得意」を分ける。単なる機能対応を強みと表現しない。
- `conditional` は、プラン・地域・プラットフォーム・段階公開など条件を明記する。
- `unknown` は未確認を意味し、非対応を意味しない。
- 機能が別アプリ、統合先、外部サービス、APIに限られる場合は、同じチャット内で使える機能と区別する。
- 無料枠は有無だけでなく、対象地域・プラン・利用制限・確認日を示す。価格は通貨・期間・税等の前提と共に記録する。
- UI言語と、AIとの会話言語を分ける。
- 提供企業の拠点国と、利用可能な国・地域を分ける。
- サービス名、機能、価格、提供状況は変化するため、根拠URLと確認日を表示・管理する。
- 料金、地域、機能の値は、公式一次ソースで確認するまで仮値または `unknown` とする。

## 7. 非機能要件

- 初期版は構造化ファイルを用いた静的配信を優先し、メンテナンスしやすくする。
- スマートフォンでも検索・比較しやすいレスポンシブUI。
- キーボード操作、スクリーンリーダー向けラベル、十分なコントラストを考慮する。
- 情報の根拠と更新日を追跡可能にする。
- 特定の企業・モデルの宣伝や性能順位を示すサイトと誤解されないよう、中立的な表現を使う。
- サイト名「AI Atlas」の公開上の利用可否、既存名称・ドメインとの重複は公開前に確認する。

## 8. 初期版の受け入れ条件

- 調査候補と公開対象が区別され、未検証の候補は公開データに混ざっていない。
- 掲載する各サービスに公式URLと一次ソースがある。
- 掲載する主な機能、地域、料金、言語には適用条件と確認日があるか、未確認として明示されている。
- 検索・絞り込み・条件クリア・件数表示が使える。
- `unknown` と `unsupported` の表示が区別されている。
- サービス一覧をコード変更なし、または単純なデータ編集で更新できる構造である。
- モバイル画面とキーボード操作で主要な利用フローを完了できる。
